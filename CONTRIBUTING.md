# Contributing to INSFAV Thumb Fetcher

Third-party contributions are welcome. For larger changes, open an issue first, then submit a pull request to `main`.

## Project boundaries

- Keep this repository a standalone helper. Do not merge its app into INSFAV or INSFAV Plus, or change either app's package, signing key or release history.
- Keep input backups read-only. Preserve the documented InstaPro backup compatibility and supported INSFAV JSON layouts.
- Keep the app focused on profile thumbnails. Do not add post, story or video downloading, cloud sync, or undocumented account-management behavior.
- Preserve output compatibility: `.thumbnails/<normalized-username>.webp`, 256 × 256 for new images, and valid legacy 128 × 128 thumbnails.
- Only write thumbnail output through the selected output folder and its granted Android storage access. Do not delete or rewrite user source media.
- Preserve account-to-image checks, bounded queues, random pacing, working-hour scheduling and Android lifecycle limits. Failures and unavailable pages must not be reported as proof that an account was deleted.
- Respect login challenges, CAPTCHA, rate limits, Retry-After and explicit access restrictions. Do not add bypass behavior or repeated retries that ignore them.
- Keep cookies encrypted in private app storage and out of logs. Never commit real cookies, personal JSON backups, usernames, session data, signing keys, keystores, passwords or other secrets.

## Releases and forks

Official releases must use the existing private release key. Forks may build and distribute their own versions, but must not describe them as official BlackWare releases or claim update compatibility with BlackWare-signed APKs. Never publish signing secrets in a fork.

Do not overwrite or delete published release tags or assets. A pull request is a proposal; maintainers decide whether it is included in an official build.

## Pull requests and checks

Describe the user-visible change, why it is needed, and how you verified it. Include screenshots for UI changes and note any checks you could not run.

Use JDK 17 and run the applicable checks:

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease :app:assembleDebugAndroidTest
node --test tools/profile-probe.test.cjs
```

The debug APK signing key generated by GitHub Actions is not persistent. Do not present a debug APK as an official, update-compatible release.
